# 株式会社エージェントパートナーズ｜コーポレートサイト 画面UI資産（v2.0）

デザインコンセプトは **Trusted Partner ── 誠実・堅実・先進**（`redesign-proposal.html` 準拠）。
**ディープネイビー × ウォームグレー × 抑制ゴールド**を基調とした「選ばれる信頼」のコーポレートサイトです。
外部ライブラリ不要。`index.html` をダブルクリックするだけでブラウザで動作します。

## ブランド（デザイン v2.0：Trusted Partner）
| 役割 | 色 | コード |
|---|---|---|
| 基幹色（信頼・重心） | ディープネイビー | `#0E1B33` / `#1C2E52` / `#33497A` |
| アクセント（線と点のみ。面塗り禁止） | 抑制ゴールド | `#A8863C` / `#C9AE6E` |
| 交互セクション背景 | ウォームグレー | `#F7F6F3` |

- 見出し：明朝（Noto Serif JP）は H1/H2 のみ。数字・英字ディスプレイは Libre Baskerville
- 本文・UI：Noto Sans JP（15.5px / 行間1.9）
- 角丸は 4〜8px、影は hover 時の境界表現のみ。ボタンは矩形3系統（主＝ネイビーベタ / 副＝ネイビー細枠 / アクセント＝ゴールド枠線のみ）
- `css/style.css` 冒頭の `:root` 変数で配色・角丸・余白を一括変更可能
- デザインの意図・新旧比較は `redesign-proposal.html`（社内資料）を参照

## 開発事例の追加方法（cases.html）
`js/cases-data.js` の `CASES_DATA` 配列にオブジェクトを1件追記するだけで、一覧に自動反映されます（HTML編集不要）。
書式・記入例はファイル冒頭のコメントを参照してください。

## コラム記事の追加方法（blog.html）
1. 既存の記事ページ（例：`blog-subsidy.html`）をコピーして新しいファイル名で保存
2. `<title>` / meta / パンくず / 記事本文（`.article-head` と `.article-body`）を書き換え
3. `blog.html` のカード一覧に新記事のカード（`.post-card`）を1枚追加（新しい記事を先頭に）

## 実装済みの主な仕掛け
- ロゴの「つながり」を象徴する**ネットワーク背景アニメ**（白×金・Canvas）
- スクロール連動フェードイン／数値カウントアップ（`prefers-reduced-motion` 対応）
- レスポンシブ（PC / タブレット / スマホ）＋ モバイル追従CTA・ハンバーガーメニュー
- 専門用語のインライン注釈（例：AIエージェント＝“デジタル社員”）
- お問い合わせフォーム（フロント側のデモ送信。実運用時はサーバー連携を追加）

## FAQ・チャットボットの仕組みと運用
- **ナレッジベースは1か所**：`js/faq-data.js` の `AP_FAQ` 配列を編集すれば、**FAQページとチャットボットの両方**に反映されます（二重管理不要）。
- **Q&Aの追加方法**：`AP_FAQ` に `{ id, cat, q, keywords:[...], a, links:[...] }` を1件追記するだけ。`keywords` は表記ゆれ・略語・関連語を多めに入れるほど、チャットの当たりが良くなります。
- **チャットボットの照合方式**：バックエンド/APIキー不要のキーワード・スコアリング。日本語の全角半角・カタカナ/ひらがなのゆれを吸収。確度が低い質問は「候補提示」や「カテゴリ選択」、最終的に**お問い合わせ導線**へ誘導します。
- **常駐位置**：画面右下のチャットボタン。スマホでは追従CTA（無料相談）を左下へ自動退避し干渉回避。
- **発展（任意）**：より高度なAI回答が必要になった場合は、`chatbot.js` の `handle()` を生成AI API 呼び出しに差し替え可能（`AP_FAQ` を回答の根拠データとして渡す設計）。

## チャット入力の管理画面（admin.html）＋ 簡易ファイルDBサーバー
訪問者がチャットボットに入力・選択した内容を把握する社内向け画面です。
保存先は外部DB不要の **ローカルファイル（NDJSON）= `server/data/chat-logs.ndjson`** を簡易データベースとして使います。

### 推奨：サーバー経由（全訪問者分を集約）
```bash
cd html/server
npm start      # = node server.js（依存ライブラリなし）
```
→ ブラウザで `http://localhost:3000/admin.html` を開く。詳細は [`server/README.md`](server/README.md)。
- チャット入力は `POST /api/chat-log` でファイルに追記され、管理画面は `GET /api/chat-logs` で全件を読み出します。
- 管理画面上部のバナーに「データ取得元：サーバー簡易DB」と表示されます。

### フォールバック：サーバー未起動／`file://` 直接閲覧
- `chatbot.js` は `localStorage` に記録、`admin.html` は `localStorage` を表示（取得元バナーに表示）。デグレなしで動作します。

### 管理画面の機能
- 簡易パスフレーズ＝`agent-admin`（`admin.html` 内 `ADMIN_PASS`／**運用前に必ず変更**）。公開ナビには非掲載。
- 統計（総数・回答済・未回答・未回答率）／**未回答ワードTOP10**（FAQ追加の優先候補）／検索・種別・回答状況フィルタ／CSVエクスポート／ログ消去／サンプル投入（動作確認用）。

### データ構造（簡易DB）
- 実体：`server/data/chat-logs.ndjson`（1行=1レコードのJSON。追記型）
- レコード：`{ t, page, q, source, matched, id, score }`
- バックアップ＝ファイルコピー、初期化＝ファイルを空に（管理画面の「ログ消去」でも可）
- 将来MySQL等へ移行する場合も、`server.js` の読み書き部分のみ差し替えればAPI契約・画面は不変更。

### セキュリティ／個人情報
- 簡易ゲートは本格認証の代替にはなりません。公開運用時はサーバーに `ADMIN_TOKEN` を設定（`admin.html` の `ADMIN_TOKEN` に同値）＋HTTPS／アクセス制限を。
- `/server/` 配下（コード・DBファイル）は静的配信から遮断済み。パストラバーサル防御済み。
- 自由入力にはPIIが含まれ得るため、保管期間は社内ルールに従い、不要時は「ログ消去」を。
